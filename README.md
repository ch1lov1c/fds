# WEBNICSS — сайт в одной папке

Обновлено 31 октября 2026 года. Все файлы сайта лежат непосредственно в одной папке. Откройте `index.html` или запустите локальный сервер; для переходов между страницами в Workspace используйте живой предпросмотр. Краткая инструкция — `НАЧНИТЕ-ЗДЕСЬ.txt`.

## Изменения

- На главной перед подвалом находится адаптивная форма обсуждения проекта. В каждой из 35 карточек услуг есть Telegram, ВКонтакте и «Обсудить проект»; последняя кнопка открывает форму с предвыбранной услугой.
- Предложены ориентировочные цены «от». Это не утверждённый прайс: проверьте суммы, состав работ и сроки перед публикацией. Окончательные условия согласовываются индивидуально.
- В подвалах страниц и документах указан адрес `info@webnicss.ru`. Получение писем на него этой сборкой не проверялось.
- Обновлены политика конфиденциальности, отдельное согласие, условия заказа и раздел безопасности. До включения формы владельцу необходимо проверить документы на соответствие фактической обработке, настройкам сервиса и законодательству; самостоятельная юридическая проверка сайта этой сборкой не проводилась.
- Удалены корзина, витрина подписок и Telegram-товаров, продажа доступов и API-ключей, рекламное направление, карточка WordPress и блок с открывающейся коробкой. Услуги по работе с ИИ, оформлению Telegram и разработке ботов сохранены. `shop.html` и `product.html` — страницы для старых ссылок без каталога.
- Копии до прежних и текущих изменений находятся отдельно: `WEBNICSS-backup-before-changes-2026-10-30.zip` и `WEBNICSS-backup-before-form-2026-10-31.zip`. Не распаковывайте резерв поверх новой версии, если не хотите отменить изменения.

## Форма и Telegram

Форма подготовлена для сервиса Zapnoty, но **не подключена и отключена** до установки публичного ID. Она сама не отправляет данные в Telegram и не использует токен бота. Чтобы получить реальные заявки, владелец создаёт аккаунт и форму в Zapnoty, привязывает Telegram, создаёт маршрут уведомления, ограничивает домены и устанавливает публичный ID формы. Порядок действий и проверки — в `НАСТРОЙКА-ФОРМЫ.txt`.

Проверяйте заявку и в кабинете Zapnoty, и в Telegram. Ответ API `{ok:true}` означает только полученный ответ сервиса: фильтры, маршрут, доступность мессенджера и лимит уведомлений влияют на доставку. Локальные и автоматические тесты в этой сборке не подтверждают реальную доставку.

## Основные файлы

- `index.html`, `projects.html`, `service.html` — страницы сайта; `shop.html`, `product.html` — страницы для старых ссылок.
- `privacy.html`, `consent.html`, `terms.html`, `security.html` — политика, отдельное согласие, условия и безопасность.
- `main.js`, `bootstrap.js`, `styles.css`, `legal.css`, `core3d.js`, `fonts.css`, шрифты и изображения — оформление и логика сайта.
- `watch3d.bundle.js` — интерактивная сцена часов; `watch3d.js`, `OrbitControls.js` и `three.module.js` — её исходные файлы. Для пересборки: `npx --yes esbuild@0.25.5 watch3d.js --bundle --format=iife --target=es2020 --legal-comments=inline --outfile=watch3d.bundle.js`.
- `.htaccess` — дополнительные заголовки и ограничения только для Apache 2.4. На Nginx, GitHub Pages и Python он не действует. `release-check.js` — проверка; инструкции находятся в `TESTS-README.txt`.

## Локальный просмотр

Откройте `index.html` в браузере. В просмотрщике файлов Workspace главная показывает встроенный автономный вариант со стилями, меню, внутренними якорями и 3D-фигурой. Поскольку просмотрщик не загружает соседние файлы и сеть, переходы на другие страницы и реальная отправка доступны в живом предпросмотре или обычном браузере на опубликованном домене.

Встроенный вариант собирается из реальных `styles.css`, `fonts.css`, `main.js`, `core3d.js`, шрифтов и картинок. После изменения этих файлов обновите его командой `python3 build-workspace-preview.py`. Для сборщика нужен Python 3; Pillow при наличии сжимает встроенные изображения. Не редактируйте вручную участки `WORKSPACE-...` в `index.html`: они пересоздаются и снабжаются CSP-хешами. Обычная версия использует отдельные файлы CSS и JS.

Для локального просмотра запустите в папке сайта `python3 -m http.server 8080 --bind 127.0.0.1` (Windows: `py -m http.server 8080 --bind 127.0.0.1`) и перейдите на `http://localhost:8080/`. Zapnoty не позволяет добавить localhost в разрешённые источники, поэтому реальную отправку проверяют на опубликованном HTTPS-домене.

## Публикация и безопасность

Эта сборка статическая: оплата, WordPress и автовыдача к ней не подключены. Внешний Telegram-бот не изменялся. Не передавайте пароли, токены или коды подтверждения; в браузерном коде они не нужны. Антиспам и ограничение источников должны быть настроены и проверены в Zapnoty; клиентская проверка не защищает от прямых запросов к API.

При обновлении существующего хостинга замените старые страницы и `main.js`, а также удалите из опубликованной папки старые файлы удалённых товарных изображений `product-*.jpg` и старый CSV товаров. Файлы в истории GitHub автоматически не стираются. После загрузки проверьте сайт на телефоне, старые ссылки, форму и уведомления.

Не загружайте в публичный веб-корень README, `*.txt`, `*.md`, `*.py`, CSV, архивы и `release-check.js`: они нужны только владельцу. На GitHub Pages `.htaccess` не действует. Перед запуском настройте HTTPS, резервное копирование, права доступа и ограничения на стороне хостинга, сверьте документы и уведомления оператора персональных данных.

Инструкции по прежним планам WordPress/WooCommerce и Robokassa сохранены только в резервной копии. Они относятся к прежней сборке; подключений или реальных платежей нет. При дальнейшей настройке платёжного модуля сначала устраните и перепроверьте отмеченные ранее вопросы сверки суммы и повторных уведомлений.
