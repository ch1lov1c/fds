# WEBNICSS — сайт в одной папке

Обновлено 30 октября 2026 года. Все файлы текущей версии находятся непосредственно в одной папке. Откройте `index.html` или запустите локальный сервер. `НАЧНИТЕ-ЗДЕСЬ.txt` содержит краткий порядок действий.

## Что изменено

- Первый экран адаптирован для телефонов: знак © расположен рядом с логотипом, описание и обе кнопки помещаются на первом экране. Сохранён дизайн и вращение 3D-фигуры перетаскиванием.
- Удалены корзина, витрина подписок и Telegram-товаров, продажа доступов и API-ключей, рекламное направление, карточка про WordPress и блок с открывающейся коробкой. Услуги по работе с ИИ, оформлению Telegram и разработке ботов сохранены, но продажа Premium и Stars удалена.
- `shop.html` и `product.html` оставлены как безопасные страницы для старых ссылок: они показывают, что раздел больше не используется, и предлагают перейти к услугам или проектам. Каталога и товаров в них нет.
- Описания в документах обновлены под текущую версию. Политика и условия заказа остаются проектами и требуют проверки перед публикацией. Ориентировочные цены услуг не утверждены владельцем.
- Резервная копия до удаления находится отдельно: `WEBNICSS-backup-before-changes-2026-10-30.zip`. В ней сохранены прежние страницы, товары, изображения, инструкции и данные. Не распаковывайте её поверх новой версии, если не хотите отменить изменения.

## Основные файлы

- `index.html`, `projects.html`, `service.html` — страницы сайта.
- `shop.html`, `product.html` — страницы для старых ссылок без каталога.
- `privacy.html`, `terms.html`, `security.html` — документы, требующие проверки.
- `main.js`, `bootstrap.js`, `styles.css`, `legal.css`, `core3d.js`, `fonts.css`, шрифты и изображения — оформление и логика сайта.
- `watch3d.bundle.js` — готовая интерактивная сцена часов; `watch3d.js`, `OrbitControls.js` и `three.module.js` — её исходные файлы. Для пересборки: `npx --yes esbuild@0.25.5 watch3d.js --bundle --format=iife --target=es2020 --legal-comments=inline --outfile=watch3d.bundle.js`.
- `.htaccess` — дополнительные заголовки и ограничения только для Apache 2.4. На Nginx, GitHub Pages и Python он не действует. `release-check.js` — проверка; инструкции находятся в `TESTS-README.txt`.

## Локальный просмотр

Откройте `index.html` в браузере. В просмотрщике файлов Workspace главная также показывает встроенный автономный вариант со стилями, меню, внутренними якорями и 3D-фигурой. Поскольку этот просмотрщик не загружает соседние файлы, переходы на другие страницы доступны в **живом предпросмотре сайта** или обычном браузере.

Встроенный вариант собирается из реальных `styles.css`, `fonts.css`, `bootstrap.js`, `main.js`, `core3d.js`, шрифтов и картинок. После изменения этих файлов обновите его командой `python3 build-workspace-preview.py`. Для работы сборщика достаточно Python 3; Pillow при наличии сжимает встроенные изображения. Не редактируйте вручную участки `WORKSPACE-...` в `index.html`: они пересоздаются и снабжаются CSP-хешами. Обычная версия по-прежнему использует отдельные файлы CSS и JS.

Если браузер ограничивает локальные скрипты, выполните в папке сайта `python3 -m http.server 8080 --bind 127.0.0.1` (Windows: `py -m http.server 8080 --bind 127.0.0.1`) и перейдите на `http://localhost:8080/`.

## Публикация и безопасность

Эта сборка статическая: оплата, WordPress и автовыдача к ней не подключены. Внешний Telegram-бот не изменялся. Не вводите в чат и не передавайте посторонним пароли, токены или коды подтверждения.

При обновлении существующего GitHub Pages или другого хостинга недостаточно просто добавить новые файлы: замените старые страницы и `main.js`, а также **удалите старые файлы удалённых товарных изображений `product-*.jpg` и старый CSV товаров** из опубликованной папки. Новая сборка их не содержит. Файлы в истории GitHub автоматически не стираются. После загрузки проверьте опубликованный сайт в телефоне и старые ссылки.

Не загружайте в публичный веб-корень этот README, `*.txt`, `*.md`, `*.py`, CSV, архивы и тест `release-check.js`: они нужны только владельцу. На GitHub Pages `.htaccess` защиту файлов не обеспечивает. Перед запуском проверьте контакты, документы, HTTPS, резервное копирование и права доступа.

Инструкции по прежним планам WordPress/WooCommerce, Robokassa и старые тесты сохранены только в резервной копии. Они относятся к прежней сборке; подключений или проведённых реальных платежей нет. При дальнейшей настройке платёжного модуля сначала устраните и перепроверьте отмеченные ранее вопросы сверки суммы и обработки повторных уведомлений.
